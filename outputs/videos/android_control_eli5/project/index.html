AndroidControl ELI5 explainer
1. What problem are we solving?

Teaching a small vision-language model to use Android apps.

The agent sees a goal and a phone screen.

  • Goal: "Add Alice as a contact."
  • Input: screenshot plus UI state.
  • Output: structured action JSON.
  • Hard part: grounding tiny UI targets, not just writing valid JSON.
Tap "Create contact"
{"action":"tap", "element_id":7}
ELI5 version: we are trying to teach a phone-using robot what to press next, from the same kind of screen a person sees.
2. AndroidControl setup

Step-level supervised fine-tuning on AndroidControl.

Data

One row is one screen plus one target action. Final a11y-native setup used 73K train rows, 686 validation rows, and 8,217 test rows.

Model

Gemma 4 E2B with Unsloth QLoRA. About 29.86M trainable parameters, only 0.58% of the base.

Hardware

Single RTX 4090, 24 GB VRAM. Run A took 19,886 steps, one epoch, and 8 h 41 min.

119 MB

final adapter size

Research question

Can a 2B-class VLM beat its zero-shot AndroidControl policy, and which task formulation makes the signal learnable?

This was a constrained class-project setup: fast iterations, checkpoint sweeps, and representation changes instead of giant pretraining.

4. Why coordinate prediction failed

Coordinates looked universal, but the loss did not understand space.

Original target

{"action":"tap", "x":0.293, "y":0.934}
  • Token CE rewards digit strings.
  • It does not reward "near the right button."
  • Small buttons shrink after vision downsampling.
Cancel
Send
The model learned plausible screen spots, like center or top-left, instead of reliably grounding the actual UI element.
5. Pivot to accessibility element IDs

Instead of exact pixels, give the robot a menu of buttons.

Set-of-Marks path

Overlay numbered marks on interactable elements. Conceptually nice, but zero-shot was only 0.130 for this 2B VLM.

Accessibility-native path

[7] Button "Send" bbox=(...) [8] TextField "Name" bbox=(...) {"action":"tap", "element_id":7}

Before

Predict coordinates from pixels.

After

Select from UI nodes already known to Android.

Zero-shot

Element accuracy started at 0.3935.

This was the main insight: mobile control works better as structured action selection over UI state than as raw coordinate regression.
6. Metric pivot to element accuracy

The metric had to match the action we actually execute.

Legacy tap-radius

  • Correct if near the ground-truth point.
  • Useful for coordinate-era comparison.
  • Can forgive the wrong nearby element.

Element accuracy

  • Correct only if element_id matches.
  • Matches production behavior.
  • Made the learning curve meaningful again.
If two buttons sit side by side, being close is not enough. The wrong button still fires the wrong handler.

8. CAP schema and history improvements

Run K fixed action structure. Run L fixed part of temporal context.

CAP-style schema

{"action_type":"tap", "action_args":{"element_id":7}}

Generate the action type first, then type-specific arguments. Open_app improved by +69.9 points versus Run I.

One-step history

Previous action: {"action_type":"scroll", "action_args":{"direction":"down"}}

Scroll accuracy moved from 21.5% to 39.8% by reducing a direction-convention flip.

Small schema choices were not cosmetic. They changed which classes the model could learn cleanly.

10. AndroidWorld transition

Per-step success does not automatically become episode success.

P(success) = pN

If every step is 85% correct, a 15-step episode succeeds only about 8.7% of the time.

AndroidControl vs AndroidWorld

  • AndroidControl: static screenshots, one row equals one step.
  • AndroidWorld: live emulator, 116 tasks, whole-episode success.
  • Distribution shift: new prompt style, rollout errors, terminal decisions.
This is why the AndroidControl win is real, but live deployment is a separate research problem.

12. Future work and conclusion

Final lesson: element-native control works; multi-step agency needs trajectory training.

Trajectory replay

Train on complete successful AndroidWorld episodes, not isolated rows.

Schema enforcement

Use JSON grammar decoding so illegal actions cannot be emitted.

ReAct / reflection

Match the live harness prompt and add screen-diff memory.
